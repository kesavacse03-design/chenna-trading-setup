# Strategy runtime (backtester)

This folder contains a tiny backtesting runtime used by the CTS dashboard.

Contents (key files):
- backtester.cjs – Orchestrates prefetch → replay → strategy → simulator → outputs
- replayEngine.cjs – Iterates cached OHLCV candles
- simulator.cjs – Simple market/limit fill simulator with slippage
- strategyBase.cjs – Breakout strategy example
- dataAdapter.cjs – Mock and Upstox adapters for OHLCV
- output/ – Results, trades CSV, suggestions, run artifacts

## Running a mock backtest

- From workspace root or backend folder, you can invoke the runner:

  - Node:
    node ../../backend/strategy/runner.cjs --symbols TCS,RELIANCE --from 2025-10-30 --to 2025-10-30 --interval 5m --mode mock

  - Using the backend package.json shortcut:
    npm run strategy:run

Outputs are written under backend/strategy/output:
- <runId>-results.json – aggregate metrics + per-category
- <runId>-trades.csv – trades list
- <runId>-suggestions.json – Phase G “shadow learner” proposals for losing trades

## Switching to Upstox mode

- Ensure the backend server is running with valid Upstox credentials.
- Set UPSTOX_API_BASE (default http://localhost:3001).
- Pass --mode upstox to the runner, or call the server endpoint /strategy/run with mode=upstox.
- The backtester will prefetch OHLCV via the server and fall back if needed.

## Tests

A small test harness lives in __tests__/run-tests.cjs:
- Replay engine step test
- Simulator fill test
- End-to-end mock backtest (verifies results/trades/suggestions files)

Run from backend folder:
- node ../../backend/strategy/__tests__/run-tests.cjs

Or add an npm script wired to the backend package.json if desired.
